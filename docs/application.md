# Локальное приложение передачи и проверки

Приложение сохраняет планы, добровольное согласие владельцев, наблюдения, закрытые решения и принятие следующего действия. Next.js показывает формы; Rust проверяет данные, пересчитывает знаменатели и отказывает в переписывании принятой истории. Начальный рабочий набор пуст. Учебные числа появляются только после отдельной кнопки «Добавить вымышленный учебный пример» и подтверждения.

## Запуск

Нужны Node.js 22+, pnpm 10.33.0 и Rust 1.88+. В корне **этого репозитория**, а не родительского проекта:

```powershell
pnpm install --frozen-lockfile
pnpm setup
pnpm dev
```

`setup` просит выбрать пароль локальной среды и создаёт `.env.local` с ним и случайными серверными секретами. Он не перезаписывает существующую настройку. Не публикуйте этот файл и не вставляйте его значения в материалы или issue. Откройте `http://127.0.0.1:3005/ru`, войдите с выбранным паролем. Rust API слушает `127.0.0.1:3006`; web слушает `127.0.0.1:3005`. Это локальная закрытая среда с одним общим операторским доступом; не открывайте её в интернет без отдельной модели доступа и развёртывания.

Если порты заняты, завершите другой локальный запуск до старта. `pnpm dev` запускает оба процесса; остановка командой Ctrl+C завершает сессию. Данные остаются в `data/state.json` в корне этого репозитория при стандартном запуске; рабочий путь определяется `DATA_FILE` и каталогом Rust-процесса. Не копируйте рабочие записи в публичные templates/ или examples/.

## Реальный рабочий путь

1. Создайте эксперимент: один вопрос, сценарий, baseline, ограничения, равный плановый объём фаз, порог успехов, лимит попытки, stop-rule с возвратом, две роли и дату разбора. До принятия можно изменить план.
2. После фактического согласования запишите добровольное согласие обеих ролей, время и источник подтверждения. Принятый объём и критерии становятся неизменяемыми. Без согласия начатые попытки не принимаются.
3. Вносите каждое наблюдение по времени. `completed` означает корректное выполнение без помощи в пределах лимита. `failed` означает помощь, ошибку, тайм-аут или прерывание после старта. `not_started` обозначает отмену до начала, с временем 0 и причиной. Сохранённый факт нельзя переписать или удалить.
4. При stop-rule не начинайте новые попытки. После его фиксации можно отметить неначатые отменённые задания. Закрывайте эксперимент решением `stop`, включая возврат к прежнему порядку. Для новой проверки после исправления создайте новый эксперимент.
5. Запишите `continue`, `stop` или `iterate` с причиной, доказательствами, временем, следующим действием и дедлайном. Закрытое решение и наблюдения неизменяемы. `continue` разрешено только при полном плане начатых попыток обеих фаз, достигнутом пороге, результате не хуже baseline и отсутствии stop-rule.
6. Следующий шаг отдельно принимает добровольно согласившийся владелец: роль, время, предел работы и подтверждение. При отсутствии владельца сохранённое решение остаётся в статусе «следующий шаг не принят». Приложение не начинает следующий этап и не делает участие после хакатона обязательным.

Даты задаются `YYYY-MM-DD`. Поля времени используют местное время браузера и сохраняются с часовым поясом в формате RFC3339. Решение не может предшествовать наблюдениям; принятие шага не может предшествовать решению. Отображаемое время сохранено в UTC или исходном смещении. Публикуя итог, укажите дату, плановый объём, числитель, знаменатель и ограничения отдельно.

## Знаменатели и границы решений

Rust считает `started = completed + failed` отдельно для baseline и прототипа. Все неудачи после начала остаются в знаменателе. `not_started` показывается отдельным счётчиком и не добавляет попытку. `0/0` означает отсутствие наблюдений, а не нулевую эффективность. Каждая фаза содержит не более планового числа заданий, включая неначатые. Полный объём продолжения требует именно N начатых попыток; отмена оставляет проверку неполной.

Одно stop-rule имеет приоритет над любой метрикой; `iterate` и `continue` при нём отвергаются сервером. `iterate` закрывает текущий этап до исправления или нового плана и допустим при недостатке данных. Маленькая проверка не доказывает пользу для организации, готовность к нагрузке или коммерческий эффект. Время — наблюдаемый факт, а не автоматически рассчитываемое обещание экономии.

## Данные и ограничения доступа

Рабочий набор `Data` содержит `experiments`. Каждый эксперимент хранит план, принятие исходного объёма, список наблюдений, необязательное закрытое решение `decision` и отдельное принятие `handover`. `Analysis` возвращает серверные счётчики по фазам, `stop_triggered`, `can_continue` и статус. Неизвестные поля отвергаются во всех вложенных Rust-структурах. ID уникальны, строки ограничены по размеру, даты и числовые пределы проверяются сервером.

Сохранение использует номер версии. Другая вкладка не может молча перезаписать новые записи: конфликт требует загрузки актуального набора. Перед загрузкой скопируйте несохранённый текст. Сохранение файла выполняется до смены состояния в памяти; ошибка диска оставляет прежнюю сохранённую версию. Доступ к API требует серверный токен, браузер получает только защищённую web-сессию.

Общий локальный пароль идентифицирует допущенного оператора, а не конкретного владельца из формы. Подтверждение согласия — запись оператора о фактической договорённости; приложение не проверяет подписи и не передаёт права на код, данные или призы. Пользуйтесь ролями и безопасными ID, не вводите лишние персональные данные, токены, закрытые документы или секретные ссылки. Без согласованных рабочих данных начните на синтетическом наборе.

Для правки ошибочного сохранённого факта закрывайте текущий эксперимент с объяснением и создавайте новый; старый факт остаётся как наблюдение того этапа. Принятое действие также не переписывается. Если владелец больше не участвует, отдельно зафиксируйте остановку процесса в своей операционной записи; новый объём оформляется новой карточкой. Приложение не ведёт реестр исполнения задач и не подтверждает удаление исходных данных — выполняйте и фиксируйте эти действия по [workflow](workflow.md).

## Проверки

```powershell
pnpm typecheck
cargo test --manifest-path backend/Cargo.toml --locked
```

Доменные Rust-тесты проверяют исключение неначатых заданий из знаменателя, приоритет stop-rule, полный baseline для continue, запрет переписывания доказательств и критериев, добровольность и неизменяемость принятия, неизвестные поля и неверные даты. Общие серверные тесты проверяют доступ, версию сохранения и отказ записи диска. Команда не доказывает ручную проверку интерфейса; перед использованием пройдите сценарий от пустого плана до решения и принятия.
