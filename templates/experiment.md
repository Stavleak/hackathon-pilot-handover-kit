# Карточка ограниченного эксперимента

Выберите правила до первого наблюдения. Заполненную карточку и журнал храните в закрытом каталоге. Примеры ниже в полях отсутствуют намеренно: впишите свой процесс, а не переносите учебный порог без обоснования.

## Вопрос и граница

| Поле | Значение |
|---|---|
| `project_id` / `experiment_id` | [ID проекта] / [ID эксперимента] |
| Владелец процесса / технический владелец | [согласившиеся роли] |
| Гипотеза | [кто выполняет действие; что изменится; что опровергнет предположение] |
| Один сценарий | [вход → действие → наблюдаемый выход] |
| Что не входит | [реальная нагрузка; прочие роли; другие процессы] |
| Версия прототипа и артефакты | [точная версия; ID реестра] |
| Разрешённый набор | [синтетический или явно разрешённый; ID набора] |
| Период и разбор | [начало/конец; время и UTC-смещение; дата решения] |
| Ресурсы и добровольное участие | [ограничение времени; подтверждённые роли] |

## Baseline и сравнение

- Прежний способ выполнения: [что человек делает без прототипа].
- План baseline: [сколько попыток; какие задачи; в каких условиях].
- План прототипа: [сколько попыток; какие задачи; порядок].
- Сопоставимость: [одинаковая сложность/лимит/критерий; как уменьшаем эффект обучения].
- Ограничения: [малая выборка, повтор задач, наблюдатель; что мешает обобщению].
- Где baseline и последующие наблюдения: [закрытый журнал; `artifact_id`].

Если baseline ещё не измерен, статус `planned`, а не «улучшение». Нельзя задним числом подобрать baseline из удобных попыток.

## Метрика и решение

| Поле | Определение до запуска |
|---|---|
| Основная метрика | [например завершение конкретного действия без помощи] |
| Числитель | [точное условие успеха; в какой момент ставим 1] |
| Знаменатель | Все начатые допустимые попытки в соответствующей фазе; помощь, ошибка, тайм-аут и прерванная после начала попытка остаются в нём |
| Плановый объём | [baseline N; прототип N; максимум времени на попытку] |
| Порог | [конкретное X/N; требуемый полный объём; дополнительное обязательное ограничение] |
| Правило неполной выборки | [кроме stop-rule → `revise`/`archive`; не объявлять `continue` по удобным первым строкам] |
| Дополнительное наблюдение | [время/ручные исправления; определение; не меняет основной порог] |
| Немедленная остановка | [наблюдаемый триггер; любое одно срабатывание важнее достижения метрики] |
| Кто может остановить | Владелец процесса, технический владелец и любой наблюдатель; решение записывает владелец процесса |
| Возврат | [как выключаем прототип и возвращаем прежний способ; проверенный владелец] |

Успех без помощи требует корректного выхода, соблюдения обязательных правил и завершения до лимита. Помощь автора не превращает неуспех в успех. Неначатую отменённую задачу укажите отдельно как `not_started`; в знаменатель попыток она не входит. Повтор после исправления получает новый `experiment_id`, версия и порог фиксируются заново.

Не меняйте порог после просмотра результатов. При изменении гипотезы, задач, версии или допуска закройте текущую карточку и начните новую. На маленькой выборке показывайте X/N и ограничения, без утверждений о статистической достоверности.

## Разбор

- Baseline: [успехов / начатых; плановый объём].
- Прототип: [успехов / начатых; плановый объём; неначатых].
- Stop-rule: [нет / да; попытка и триггер].
- Нарушения сопоставимости или качества данных: [что произошло].
- Вывод только для этого сценария: [поддержана / не поддержана / данных недостаточно].
- Решение: [`continue` / `revise` / `stop` / `archive`; причина].
- Следующее действие: [новый ограниченный этап или возврат/удаление/архив].
- Следующий владелец, добровольное согласие, ресурсы и дата: [значения либо этап не начинается].
- Запись: [`decision_id` и `artifact_id` доказательств в decision-log.csv].

`continue` требует полного заранее выбранного объёма, выполненного порога, отсутствия stop-rule и отдельного согласия на следующий этап. `revise` закрывает текущую проверку до исправления. `stop` останавливает этот эксперимент; он не означает автоматический запрет на идею навсегда. `archive` закрывает работу при отсутствии владельца или ресурсов.
